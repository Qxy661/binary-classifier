# 02 · 数据管线

> 真实 CV 项目里，**80% 的精力在数据**：采集、清洗、组织、加载。
> 本章讲清奶龙/塔菲项目的数据管线是怎么设计的。

## 动机

模型只是冰山一角。一个能用的分类器，数据管线的工程占比远超模型本身。
理解数据管线 = 理解真实 CV 项目的核心。

## 1. 数据从哪来

二分类项目的数据来源（按可靠性排序）：

| 来源 | 适用 | 说明 |
|---|---|---|
| **公开数据集** | 阶段1（猫狗） | HuggingFace `cats_vs_dogs`，标准、量大 |
| **网络采集** | 阶段2（奶龙/塔菲） | 搜索引擎/图床，需清洗 |
| **手动收集** | 阶段2 | 截屏/保存，质量可控但量少 |

**奶龙/塔菲为什么没有现成数据集**：它们是近期的表情包形象，还没人做成标准数据集。
所以需要自己采集——这本身就是真实项目的一环。

## 2. 数据的组织：文件夹结构

最朴素的二分类数据组织——**按类别分文件夹**：

```
data/
├── train/
│   ├── cat/    img1.jpg img2.jpg ...
│   └── dog/    img1.jpg img2.jpg ...
└── val/
    ├── cat/    img1.jpg ...
    └── dog/    ...
```

**为什么这样**：简单、可读、可检查（打开文件夹就知道每类多少张）。
很多框架（torchvision ImageFolder）原生支持这种结构。

## 3. 数据管线三步

```
原始图片 → 1. 清洗（去坏图/统一格式） → 2. 划分（train/val）
        → 3. 加载（resize/归一化/numpy）
```

### 清洗
- 删除损坏/无法打开的图片
- 统一格式（全部转 RGB、JPEG）
- 删除重复图

### 划分
- **train**（80%）：训练用
- **val**（20%）：验证泛化，不参与训练
- **关键**：val 必须和 train 不重叠，否则是"用测试集作弊"

### 加载
- resize 到统一尺寸（本项目 64×64）
- 归一化到 [0, 1]（除以 255）
- 转成 numpy 数组

## 4. 为什么 64×64 而不是原图

- **计算成本**：纯 NumPy 训练，大图太慢。64×64 是速度/信息量的平衡
- **信息保留**：猫/狗、奶龙/塔菲的区分特征（形状、颜色）在 64×64 下仍保留
- **可扩展**：PyTorch GPU 版可以用更高分辨率（如 128×128）追求效果

## 6. 数据增强（进阶，提效果的关键）

数据增强 = 训练时随机变换图片，让模型见过更多变体：

| 增强 | 作用 |
|---|---|
| 水平翻转 | 猫/狗方向不重要，防过拟合 |
| 随机裁剪 | 让模型关注局部 |
| 颜色抖动 | 让模型对光照鲁棒 |

**为什么重要**：奶龙/塔菲表情包颜色鲜艳、背景多样，增强能显著提准确率。
PyTorch 版可用 `torchvision.transforms` 轻松加；MiniTorch 版需手写。

## 小结

- 数据是真实项目的核心，80% 精力
- 组织：按类别文件夹（简单可靠）
- 管线：清洗 → 划分 → 加载
- 64×64 是速度/效果平衡
- 数据增强是提效果的关键
